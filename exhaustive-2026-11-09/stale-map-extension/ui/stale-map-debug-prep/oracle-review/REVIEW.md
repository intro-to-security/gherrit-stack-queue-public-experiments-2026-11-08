2. Click the final ordinary confirmation once and observe the intended **XHR/fetch breakpoint before the initiating send**. Record debugger pause reason, exact owned stack URL, POST method, source location/call frame and scope identity. It must be the dispatch call, not a status GET, a function after send, or an await of an already dispatched request. If available through ordinary DevTools inspection, record the prepared old map/body. Do not inspect unrelated variables or authentication headers.

Retain the orchestration order: pause observation → push dispatch/ack → B1 ref read → same-pause observation → resume. The proof depends on establishing the documented **pre-dispatch** debugger boundary and its uninterrupted hold through the acknowledged push. If that boundary cannot actually be demonstrated, classify timing as unestablished rather than correcting timestamps by assumption.

This pause does not freeze all browser workers or GitHub. Use the fresh scope and exact request correlation to exclude an earlier initiating request; do not infer global network quiescence. ## Outcome oracle and bounded readback

Keep premise and outcome separate:

| Observation | Supported disposition |
| --- | --- |
| Actual map refreshed to B1 or pre-send ordering unproved | Failed stale-map premise. Preserve any real request/outcome; do not call this a vector-guard test. |
| Proven old map; explicit stale-head rejection; no job identity | Observed rejection of this captured stale initiation, with bounded independent ref/member readbacks. Do not generalize every 4xx or unchanged window into no future effect. |
| Proven old map; initiation admitted | Actual acceptance despite that old vector in this interface/context. Record the exact response and identified job, not aggregate success. |
| Admitted job has mixed member results or changed refs before failure | Per-member partial effects. Preserve the successful prefix and both authored inputs; failed/DONE status does not roll it back. |
| Transport loss, missing response, duplicate/unidentified initiation or unresolved job | Unknown effect. Freeze and reconcile read-only; never click/Resume/replay a second initiation to obtain a receipt. |

Use a few bounded cohorts: immediately after the response/job outcome, then one or two delayed reads under root's grant. Read actual A/B/trunk/source/archive refs, canonical PR/group identity and membership/lifecycle; fetch actual resulting objects and compare parents, trees and per-layer patches. If B rewrites, explicitly check whether B1's authored marker survives. Preserve PR/ref disagreements. A finite unchanged observation window is an observation, not cancellation or a suffix-write fence. For an admitted job, follow its known identity within one stated deadline; an unresolved deadline stops as unknown, without another native request.

The fixture's clean B0/B1 rebase controls help distinguish a stale-vector decision from an unrelated conflict. They do not establish a public compatibility promise or server target-selection instant. Report whether the vector was stale relative to acknowledged **actual Git refs**, which provider projections were available, and what the server actually returned; do not infer its internal comparison source.

## Abort and cleanup

Before the B push, abort if the intended initiation is not demonstrably held before dispatch, if any prior native request may have escaped, or if canonical/ref/payload identity is wrong. Do not advance B to manufacture the premise after a possibly sent request. A failed lease, unexpected vector, lost push acknowledgement, changed pause, reload, browser crash or spontaneous resume freezes this scope; capture evidence and reconcile without retry. Known-not-sent is a distinct proved state, not an inference from a missing Network entry.

After a successful planned Resume, do not click the initiation again. Record all network initiations correlated to the single click; if more than one appears, retain that fact and stop treating the trial as one uniquely attributed request. Any unknown effect remains retained even if the page later looks idle.

Remove only the owned test breakpoint and leave no owned page paused. If aborting at a pre-send pause, do not press Resume merely to tidy up: that can issue the write. Abandon the owned paused document through supported native UI, such as closing its owned tab without resuming, and record any uncertain send. Closing a tab/DevTools or deleting a breakpoint is not evidence that an already sent server job was cancelled. No branch/PR/group deletion, reset, repair or unrelated breakpoint/runtime cleanup is implicit.

The minimal new discriminator is therefore one prepared old-map request held across one independently acknowledged B advance, followed by its actual payload and scoped outcome. A stale modal, a button click or a HAR start timestamp alone cannot substitute for it.
